# 英雄批量推演 01：方法与边界

本批从三类局部规则检查扩展到阵容批量交锋。结果见 [summary.md](summary.md)，逐步观看见 [replays.html](replays.html)。打开 HTML 即可，无需服务或联网。

本目录保留旧随机箭头样本；当前默认机制已改为自动索敌，最新对照见[第二批](../hero-batch-02/README.md)。重跑旧机制须显式指定 `--targeting arrows`，下方命令输出到临时目录以保留历史结果。

## 阵容为什么是 220 个

前提：十二名英雄，每队选三名不同英雄，队伍内不计排列。初始两名与第二轮入场的一名是后续部署选择，不另算阵容。

| 类型 | 计算 | 数量 |
| --- | --- | ---: |
| 纯色 3 | 四个颜色，各选该色全部三人 | 4 |
| 双色 2+1 | 4 种主色 × 3 种副色 × 主色三选二 × 副色三选一 | 108 |
| 三色 1+1+1 | 四色选三 × 每色三选一 | 108 |
| 合计 | 十二选三 | 220 |

全部有序对局是 220×220＝48,400（包含镜像）；如果不区分双方位置且不含镜像，是 220×219÷2＝24,090，对应另有 220 个镜像。若以后允许重复英雄，需要重算。

本批抽取二十个阵容：四纯色、十二双色（每种主副色各一个）、四三色（每种缺色各一个）。每位英雄在抽样池里恰好出现五次；这是覆盖设计，不宣称随机样本能代表所有混色组合。完整二百二十个阵容保存在 [rosters.json](rosters.json)。

二十乘二十的有序配对含 A 对 B、B 对 A 和镜像；每对运行种子 11、12、13，再分两个法术模式，共 **2,400 局**。每个阵容的三位英雄按 ID 排序后，用种子模三轮换部署顺序，让每人都恰好一次作为第二轮增援；没有穷举所有初始位置和部署顺序。

## AI 怎样行动

模拟器是 Python 标准库脚本：[simulate_heroes.py](../../../../scripts/simulate_heroes.py)。双方使用同一套确定性贪心策略，不调用语言模型，不训练，也不预知后续随机事件。

运行环境要求 Python 3.10 或更高版本，无需安装第三方包。

每次轮到一方，枚举当前合法行动：英雄移动、陈的劝化、小牛的沟壑、莱恩的死亡之指，以及法术模式下的施法。给每个行动按当前可见收益打分，选最高的正分行动；没有正收益行动就让过。双方连续让过后交战。每次操作后重算下一方的行动。

- 移动考虑当前箭头下的输出、能否击杀、预计承伤、致死危险、狼人／小鹿的邻格收益、接近敌人和进入主动技能射程；八邻寻路，首次两步必须存在合法的连续路径。
- 死亡之指优先可击杀目标，英雄击杀分更高；劝化评价单位攻击和剩余生命；沟壑评价能阻止的攻击和可用主动技能。
- 测试法术评价伤害、击杀和实际治疗量。拥有蓝色英雄时选择同效果测试法术的蓝色版本，使宙斯能够触发。
- 同分使用稳定的行动／单位 ID 排序，不掷骰子挑行动。回放显示该步的评分，移动显示相对原位置的评分增量。不同类型评分只是启发式权重，不等同金币或胜率。

这个策略只看当前局面，尚不预测对手下一步，不会主动等待更好的控制时机，没有卡组规划或长期经济规划；回合开始小兵按约定规则自动推进，英雄不自动推进。它能暴露规则冲突、观察简单战术，不代表玩家水平。即使双方用同一 AI，也可能偏爱某类英雄，不能把结果直接归因于英雄平衡。

## 哪些东西随机

出生列、侧前方绕行、同格争抢、每轮四向箭头、赏金的 50% 被动使用固定种子。不同事件分别生成随机流，策略评分不消耗环境随机数。初始双方在中线各放两英雄两近战兵，并使用相同的四列；初始兵的箭头固定朝敌方，英雄箭头随机，保证行动前有真实交战机会。技能可能在交战前击杀或控制单位，不为强行制造普攻重新掷箭头。

首轮 A 先行动，第二轮 B 先行动，之后交替。有序配对覆盖阵容交换，但三个种子只是小规模样本，不是统计显著性保证。同种子、阵容、模式、回合数与脚本版本能重现同一行动日志。

## 两种模式

1. **heroes-only：**英雄自身能力＋原版 2 攻 4 血近战兵，没有卡牌。冰女和宙斯的施法被动不触发，不能凭这一模式评价蓝色强度。
2. **probes：**在同一战场上，每轮双方各得到一张“1 费造成 2 普通伤害”和一张“1 费治疗 2”的假想测试牌，当轮未用完不累计。这两种效果都有四色同效果版本，施法时必须有对应颜色英雄存活在场；策略有蓝色可用时优先选择蓝色版本。它们可点选全场合法单位，不攻击建筑。

第二种模式是为触发英雄能力而固定的实验条件，不是已经确定的正式卡牌、发牌、构筑或法术射程。双方手牌相同，冰女可能带来更多施法机会，宙斯可能产生额外伤害；这些事件在报告单列。没有偷偷给蓝色额外手牌，也不使用专属卡。

特别是第二轮起，两张 1 费牌通常已能由正常法力支付，因此本模式对冰女的后期回蓝价值覆盖很弱。回蓝触发事件可以检查实现，却不能据此判断她在正式法术牌库中的收益。

## 已确认并纳入的规则

- 六列八排，开局两英雄，第二轮第三英雄，后续每轮两个近战兵；常规出生在各自泉水排，满场新兵丢弃，英雄优先尝试登场。
- 每轮自动小兵移动 → 公开箭头／赏金被动 → 双方交替操作 → 统一交战。英雄每轮移动一次，普通一步八邻，首次最多两步；小兵出生后的首次自动移动最多两步。
- 普攻四向，近战一格、远程两格，每次只选方向上最近敌人；英雄移动不重掷箭头。
- 斯温仅溅射主目标垂直两侧，攻击一半向下取整；反伤只响应普攻；普通伤害扣护甲，透甲伤害不扣护甲；不会由溅射或反伤继续递归反伤。
- 狼人给八邻友军 +2 攻击、不含自身；小鹿给自身与八邻友军 +2 恢复。移动、阵亡、控制权变化后重新按当前位置评价光环。
- 小牛八向选一、直线两格，空格和友军不阻断；眩晕限制移动／普攻／主动技能，不封锁颜色，持续本轮。
- 陈、莱恩在周围两圈内点选目标，不受箭头限制；宙斯影响八邻敌人。陈保留被控兵的位置、生命、箭头，转换控制不算死亡。
- 主动技能首次登场就绪，每轮开始 CD 减一，阵亡期间继续计时，返场不重置 CD；莱恩首次施放后冷却四轮，后续分别三、二、一轮，最低一轮。
- 冰女每轮己方首次法术后回 2 当前法力，受本轮上限约束；每轮法力上限从 1 增至 10。
- 英雄第二轮阵亡时第四轮可返场；装备虽未纳入，本批不会通过阵亡产生装备处理。满场返场可替换己方非英雄单位，被替换者死亡照常发赏金。

## 本次补充的测试假设，未作为正式规则定案

- 近战：斧王、军团、斯温、小牛、狼人、赏金、幻刺。远程：宙斯、冰女、陈、小鹿、莱恩。这里的攻击距离是本作测试参数，原版 API 没有本作的棋盘射程字段。
- 英雄移动不额外耗法力／金币；主动技能不耗法力。眩晕不关闭被动或光环，受到普攻仍可反伤。
- 普攻、溅射、反伤使用同一战斗快照同时计算，再应用该快照的小鹿恢复，最后统一判死。这沿用本地原版术语表“先恢复再判死”的方向，例如 4 血受 5 伤且获得 2 恢复，最终为 1 血；是否用于正式玩法还待确认。技能和法术造成的死亡立即结算，不等待战斗恢复。
- 远程攻击其他单位时，友军不阻挡；本批不测试建筑目标选择。
- 每方容量暂设 24；英雄无可用泉水位置时优先替换泉水内友方兵，必要时为总容量替换其他己方兵；泉水全是敌军时等待下轮，不凭空挤走敌人。复活恢复满血；出生／复活的首次两步标记重新获得。新兵受阻不存入后续队列。
- 小兵移动先共同形成前到后的意图，允许跟进本批友军腾出的格；争同一格随机一个胜出，因前方失败而无法跟进者停留，不在同一步重新绕行。首次两步拆开处理。
- 赏金临时沿用兵 1、英雄 5；金币只记录收入，本批没有消费。第一次登场与复活都先于当轮出兵。冰女只在她在场时遇到本轮第一次己方法术才触发，不追溯登场前的施法。
- 不含塔、基地、泉水伤害、装备、普通抽牌、正式牌库、召唤卡或专属卡。进入后方不算获胜；八轮截止也不以剩余单位数判胜负。

## 怎样看结果

报告展示英雄阵亡、金币收入、场上单位、实际攻击、技能、法术和恢复事件。它能帮助发现“箭头经常没目标”“兵线越积越多”“首轮免费技能影响过大”等现象；还不能回答整局胜率、正式卡组强度或玩家体验。

本批八轮样本中，无牌模式的非眩晕单位交战机会有 22.3% 实际攻击、36.2% 射程内有敌人但箭头落空、41.5% 四向射程内均无敌人；测试法术模式分别是 22.7%、34.3%、43.0%。这提示下一轮值得单独比较箭头分布和进场节奏；当前并未因此自动修改箭头规则。

用户要求后新增英雄／小兵分组计数，重跑核对全部 2,400 局原有结果不变。上述整体比例是两种单位的单位×轮次加权结果，不是英雄出手率。在测试法术模式中，英雄为 36.8% 实际普攻、38.9% 箭头落空、24.3% 四向射程无敌；小兵分别为 16.6%、32.2%、51.2%。小兵占该模式非眩晕交战机会的约 69.6%。无牌模式的分组数据也已加入 summary.md。

分母为每次交战开始时仍在场且未眩晕的单位，每轮每个单位计一次；同一英雄参加多轮会重复贡献观测。普攻选到目标就计入，即使护甲把伤害减为零；技能、反伤和溅射不额外算普攻。类型按攻击方划分，附近敌人可以是英雄或小兵。“射程内无敌”只说明四个合法攻击方向内够不到，包含行军、站位及斜向相邻等情况，不能全部解释为赶路。

五个详细回放分别覆盖红蓝、红绿、红黑、带测试法术的蓝绿，以及混色交锋。所有 2,400 局只保留汇总，完整逐行动日志选择性保存；任意一局可按阵容、种子和模式单独重跑。

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/simulate_heroes.py --targeting arrows --out /tmp/artifact-arrow-reference

# 单局重跑，输出至单独目录
python3 scripts/simulate_heroes.py --a 10020,10054,10069 --b 10033,10064,10065 --seed 11 --probes --targeting arrows --out /tmp/artifact-replay
```

测试涵盖阵容计数与覆盖、同时伤害、致死反伤及护甲、法术不反伤、斯温溅射、八邻光环、恢复先于判死、对角两格眩晕、控制权转换、法力恢复上限、阵亡期间冷却、小兵跟进与争格、完整日志的种子复现。批量运行还逐阶段检查占格唯一、坐标、生命和队伍容量，以及行动阶段必然终止。
