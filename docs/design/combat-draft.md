# 战场与回合草案

更新日期：2026-11-12。

本文汇总第一版已接受的战场方案，并明确标注剩余候选与待定细则。确定项以 [初步玩法记录](initial-ideas.md) 为准。目前已有脚本模拟，尚无可玩客户端。

## 已明确的约束

- 支持铺场，每方容量若有限制应至少十个单位；满场不能新增单位。
- 自动移动在出牌之前；英雄移动改为出牌阶段的独立行动，与技能／装备交替使用，最后自动交战。
- 小兵自动移动，英雄倾向手动控制，召唤物按单位类型定义。
- 普攻自动索敌、保持合法旧目标，提前展示攻击意图；随机箭头保留为历史对照。
- 首轮必须实际接战，之后每轮都进行交战阶段；不插入全局纯行军轮。没有合法目标的个别单位可以不攻击。
- 无固定工资，单位各有死亡赏金，包含自动小兵和卡牌召唤物。

## 已接受的基础战场与新增边界

- 双方共享六列八排，每方三排普通战场加一排泉水，每格最多一个单位。双方可以穿过中线和敌方塔的位置进入敌方泉水；塔位于本方第三排和第四排之间。
- 塔不占单位格；当前不实装塔保护效果。
- 每方单位上限与棋盘总格数是两个限制，不能把四十八格自动解释为每方四十八个单位上限。
- 常规增援与英雄复活默认在本方第四排泉水出现；已接受开局两名英雄和第一批小兵直接部署前线，形成首轮可交战局面，具体随机布局与箭头约束仍待定。
- 满场返场允许替换己方非英雄单位，被替换者按死亡处理，正常给对方赏金；不能替换英雄或敌方单位。
- 最新出生区改为可被敌军入侵、会猛烈攻击入侵者的泉水；具体讨论见下文，不再沿用禁止敌人进入的约束。

## 候选二：移动

- 英雄和小兵普通一步均可进入周围八个相邻格，包含斜向、侧向和后方，不进入被占据格、不直接跳到最前排。出生／复活首次最多两格的特例保留，按两个合法单格子步处理。
- 小兵的自动决策仍按向前、侧前绕行的既定策略，不因允许八邻移动就自动加入随机后退行为；英雄可手动选择八邻空格。
- 自动单位在已有可攻击目标时可停止推进；具体目标范围与兵种行为共同设计。
- 自动兵优先前方；被友军阻挡时尝试左前或右前的空位，两侧都可用则随机。没有合法空位则停留。
- 敌人在前方时交战，不把敌人当作可随意绕开的友军障碍。
- 同批移动意图一起提交。争抢同一空格时，公开随机选一个成功者，其他单位留在原格；平局不固定偏向左侧、某一方或先创建单位。
- 允许后排跟进本批己方单位刚腾出的格子，不再采用只看移动开始占位、让整队隔格等待的方案。跟进不增加每单位的步数上限。
- 按推进方向从前到后解决跟进，不按出生顺序；同排左到右可作为遍历约定，但不能因此覆盖既定的同格争抢随机规则。双方冲突共同处理，不先完成一方全部移动再处理另一方。
- 首次两格移动拆为两次单格子步，每步检查占位，完整依赖链、绕行和争格的衔接算法仍待细化。
- 自动移动后直接进入出牌阶段，英雄移动是其中一种独立行动，与出牌、技能、装备交替操作。
- 普通一步八邻移动、每名英雄每轮移动一次已确认。移动是否额外消耗水晶／金币尚未单独明确。
- 不再采用单独的英雄移动阶段及其让过流程；行动阶段双方连续让过后交战。
- 召唤物数据分别标注推进型／驻留型等行为，例如推进士兵与固定守卫，不统一要求手动控制。
- 自动单位一步推进、侧前方绕行、同格冲突随机处理与跟进同批空位、英雄每轮移动一次已接受；复杂移动衔接、英雄移动消耗、召唤物行为细则仍待定。

## 已接受：自动索敌与攻击意图

- 用户已同意自动索敌：保持合法旧目标，失效后选择最近合法敌人，首版同距离按稳定单位 ID 顺序。英雄与小兵采用同一原则。
- 自动移动后公开目标；出牌、移动、技能等实际操作和交战结束后刷新锁定与预览。索敌不自动移动单位。
- 箭头显示当前攻击意图，无目标等待，不再通过随机转向决定是否出手。嘲讽、强制目标等效果留待对应卡牌再设计。
- 单位优先建筑，无合法单位目标时再考虑射程内建筑。本批实现只含单位，建筑的实际结算尚未纳入，见[索敌对照实验](simulations/hero-batch-02/README.md)。
- 箭头可指上、下、左、右四正方向，“前方”是箭头指向，不固定朝敌方基地；不采用斜向普攻。近战一格、远程沿箭头直线两格以内，一次普通攻击只命中一个目标，不能直接用八邻移动范围作为攻击范围。
- 单位不阻挡对建筑的攻击，射程内的建筑不因中间有单位就从合法目标中排除；是否允许隔友军攻击其他单位尚未单独确定。
- 六回合旧样本包含斜前攻击，保留为历史记录；当前四正向规则的重算见 [开局样本 02](simulations/opening-02.md)，不能用旧样本伤亡代替新结果。
- 普通攻击建筑也受距离约束，空箭头不等于可跨整个棋盘打塔；基地同理。
- 英雄移动后旧目标仍合法则保留，否则重新索敌；新入场单位在自动移动后首次公开目标。
- 交战阶段锁定双方攻击快照并同时造成伤害，是助手建议；这样一名单位当轮被击杀不会仅因处理顺序而失去攻击。具体技能触发与死亡顺序另定。

## 第一版：出生区与泉水

用户已接受泉水方案，并明确取消塔对通行的限制：

- 每方从中线向后有第一排、第二排、第三排，以及额外的第四排泉水，双方总共八排、四十八个单位位置；单位总上限仍独立待定。
- 塔位于第三排与第四排之间，不占单位格。
- 单位可以在泉水攻击、施法、提供光环，存活英雄解锁对应颜色。泉水是战场的一部分。
- 敌人允许在塔存活时就进入泉水并攻击其中单位，但会受到猛烈攻击；塔无论存活还是摧毁都不阻挡通行。
- 第一版常规增援与复活默认第四排出生；首轮初始部署单独设计以保证立即交战。若常规增援太慢，再考虑前移至第三排。
- 第一版不额外加入泉水治疗、复活加速、刷新 CD 或无敌机制。

已接受的具体方向：

1. 本次出生／复活后的首次移动最多两格，必须经过合法空格，不能穿过堵路单位；后续恢复正常步长，退回泉水不重置首次移动机会。自动兵与英雄移动仍分别遵循回合开始自动移动、行动阶段手动移动的规则。
2. 每方六列共享一座塔，塔不占单位格，也不限制通行；当前不提供护甲／减伤等塔保护效果。
3. 用户最新修正：基地替换原塔、位于相同位置，泉水独立；先破塔再破基地，不能提前入泉跳塔获胜。本次建筑距离假设与塔四十血、基地八十血见[完整对局实验](simulations/match-batch-01/README.md)。
4. 泉水攻击在交战阶段统一结算，并提前显示伤害预览，不按每次出牌重复触发；攻击泉水范围内所有敌人，具体伤害尚未确定，不攻击全棋盘。
5. 英雄留泉可作为后方指挥打法，继续解锁颜色。普通攻击和局部技能／光环受射程限制；全场型效果可由具体英雄设计明确提供，不默认所有效果覆盖全场。

出生区须有有限容量。满场允许英雄替换己方非英雄单位，但不能覆盖敌人；泉水被敌军占满时仍可能无法返场。英雄返场优先于普通新兵是候选规则；是否提供额外反压制机制须另定。

被返场英雄替换的己方单位按死亡处理，正常向对方发放赏金，不提供免费回收受伤单位的功能。

新增建筑攻击方向：塔与基地均单目标，基地攻击为塔两倍；无攻击、能一击击杀基础近战兵的攻击值做对照。保护友方英雄的转火作为另一开关，打不到的八邻目标当无事发生，不扩大四向普攻范围或自动追击。泉水继续对范围内全部入侵者结算伤害，和基地单目标攻击分开。

## 建议接下来的讨论顺序

1. 确定棋盘尺寸、自动兵和英雄移动次序、步长与占位冲突规则。
2. 细化首次出泉移动路径、建筑攻击与泉水攻击范围；塔通行不受限制，塔保护效果暂不实装。
3. 用两三回合的示例棋局推演拥堵、交锋、复活、满场和破塔，检查是否有明显卡死。
4. 再确定普通牌起手与抽取、初始金币、单位赏金、装备价格和第一批卡牌。

不把所有候选数值一次性视为已定规则，也不因原型阶段而默认删去用户明确希望保留的兵线、召唤与英雄操作。
