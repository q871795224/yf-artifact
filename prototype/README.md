# 手机单路战场 V0.4

当前版本为 V0.4，完整规则见[成长版实现说明](../docs/design/growth-implementation.md)，验证见[发布记录](../docs/releases/v0.4.md)。历史规则见[V0.3规则](../docs/design/current-rules.md)，V0.2 历史验证见[发布归档](../docs/releases/v0.2.md)，排查和发布注意见[开发复盘与运维](../docs/development/lessons-and-operations.md)。

V0.2 使用五列八排战场，并接入与本地特效工作台共享的战斗效果。V0.1 为原六列正式试玩版本，保留在 Git 标签 `v0.1`。

现在可以从第一回合手动操作，和 AI 完成一场拆塔、摧毁基地的对局。界面沿用已接受的深色石板与头像棋子设计，复用本地 Artifact Classic 原版图片与用户选定的夜魇近战兵自制图；伤害、资源、技能和胜负直接由已有 Python 推演引擎计算。

**[在线试玩](https://q871795224.github.io/yf-artifact/)**：无需运行电脑服务，也不需要同一 Wi-Fi。线上版通过 Pyodide 在独立浏览器 Worker 中运行原有 Python 引擎，页面保持响应；运行文件和美术均由本站提供。首次载入需要下载运行文件；固定版本运行环境由 Service Worker 缓存，后续直接复用，存储不可用时回退到正常网络加载。资料包与运行环境并行加载。

线上进度以种子和已执行操作保存在当前浏览器，刷新时自动恢复。菜单「本机对局」可以下载浏览器归档里的各局 JSON。手机在同一 Wi-Fi 上打开电脑提供的浏览器版，再从菜单选择「收集对局文件」，即可把下载的记录交给电脑。清理浏览器数据会移除本机归档，建议在此之前导出所需对局。

## 本地启动与手机访问

双击项目根目录的 `运行原型.command`，或在项目根目录执行：

```sh
python3 scripts/serve_prototype.py --open
```

电脑打开 <http://127.0.0.1:8765/prototype/>。手机和电脑连接同一 Wi-Fi 后，将地址里的 `127.0.0.1` 换成电脑的局域网 IP。终端按 Ctrl+C 停止服务；端口占用时可指定 `--port 8766`。游戏需要这个 HTTP 服务，直接双击 HTML 无法进行对局。不需要 npm、打包步骤、账号或外部图片／字体服务。

刷新页面或用同一规则版本重启服务后可继续同一局。默认归档目录为电脑上的 `output/playtests/`，每次成功行动会写入。右上角也可以直接导出本局 JSON。

## 怎么玩

1. 开局每方一名英雄和一个近战兵，在中线接战；第二、三轮各增加一名英雄。第二轮起每方每轮增援一个小兵，满场或泉水堵塞时不出。
2. 点击己方英雄直接显示移动范围，也可切换英雄技能或装备；点击普通牌／物品查看效果并使用。每次操作后 AI 回应一次。
3. 英雄平时移动八邻一格，每回合一次；出生／返场后的首次移动最多两格，路径不能穿过单位。小兵在回合开始自动移动。
4. 普通攻击自动按仇恨进行。绿色／红色箭头常态显示双方目标，远程虚线直接指向目标单位；可通过新命令等牌指定普通箭头。近战四向一格，远程四向两格，优先攻击单位。
5. 双方连续让过后先处理仇恨追击，再自动交战，播放近战、远程弹道与建筑炮击；技能、受击、治疗、召唤、眩晕、护甲提升、光环和阵亡使用共享特效库。遵循系统“减少动态效果”设置。结算后停留在战场供查看伤亡，点击“下一回合”继续；这一步只控制播放节奏，不花游戏行动。
6. 摧毁对手的 40 血防御塔后，同位置出现 80 血基地，下一回合激活。摧毁基地获胜；同时摧毁为平局。可以认输结束当前对局。

选目标时，棋盘下沿临时提示显示当前目标与取消按钮。取消固定操作栏；选中英雄的技能／装备按钮位于棋子内，长按或右键查看详情。预计阵亡显示灰色头像与红叉，→ 数字表示当前局面直接交战后的生命。对手头像可查看行动记录，右上角菜单可查看阵容／返场、双方行动记录、玩法说明，以及导出对局。

手机布局以棋盘为主：顶部单行显示敌塔血量、敌方法力与金币；棋盘按可用宽高缩放并居中，格子保持正方形，按可用宽高适配，攻血数值与头像分区显示。棋盘下沿保留我方建筑和回合状态；不再保留固定角色操作条，手牌区高 74–96 像素。普通牌／物品切换与我方法力、金币、让过放在同一底栏，牌库剩余数量可在菜单查看。

## 当前试玩内容（V0.4 本地开发版）

- 我方绿色狼人、陈、全能骑士；AI 红色斧王、军团、斯温。开局每方一名英雄和一个小兵，第二、三轮各增援英雄，此后每轮补一个小兵。
- 英雄在场存活到回合末获得1经验，累计3/6经验升二/三级，下轮生效。死亡保留等级、经验与永久强化。详情可查看三级面板。
- 菜单可构筑30张普通牌（固定9专属＋21自选）和10张物品，同名最多3张。保存后用于下一局。
- 起手5张，后续每轮抽1张；首轮3法力，每轮加1并刷新，上限沿用10。所有专属都需要对应英雄本人在场并达到解锁等级，包括上帝之手与全视者恩泽。
- 普通牌可花1行动、0法力重铸：先抽新牌，再归还原牌。物品不能重铸。
- 12种单位、19种普通法术、6种英雄专属，以及18件装备、4种消耗品；物品开局1张、第3/6/9…轮再抽1张，来自自己的牌堆，没有商店。
- 普通仇恨与嘲讽都在交战前尝试追击；普通箭头可改，嘲讽／决斗额外锁定。沉默、妖术、BKB和装备主动按统一状态机制结算。
- 其他地图、塔／基地、击杀赏金和单位容量沿用原型。完整数值、执行边界、验证命令见[成长版实现说明](../docs/design/growth-implementation.md)。

新版本需要开始新局；原来的 V0.3 实验类和测试仍保留作为对照。公网运行相同的 Python 引擎，通过浏览器 Worker 保存和恢复当前版本的对局。

## 静态部署

```sh
python3 scripts/build_pages.py
python3 scripts/deploy_pages.py --repo q871795224/yf-artifact
```

第一条命令生成 `dist/gh-pages`。第二条构建并推送独立 `gh-pages` 分支、首次启用 Pages；需要 `git` 和已登录的 `gh`。源码改动另行提交并推送到 `main`。采用 GitHub 内置的分支发布，不需要自建后端或额外的 workflow 授权。

静态站点只包含界面、原版图片、固定版本运行时和必要引擎资料，不发布个人试玩存档或临时浏览器输出。路径使用相对地址，支持 `用户名.github.io/仓库名/` 子目录。

## 实现

- `scripts/playable_match.py`：真人行动适配、完整合法目标、交替行动和公开状态。AI 的高收益候选与玩家可操作范围分开，允许玩家走不利位置、选择所有合法目标、替换更弱装备等。
- `scripts/simulate_finishers.py` → `simulate_expanded_match.py` → `simulate_match.py`／`simulate_heroes.py`：复用原有战斗、卡牌、出兵、资源与胜负规则，本次没有在 JavaScript 重写一套战斗计算。
- `scripts/serve_prototype.py`：Python 标准库 HTTP 服务；对局以随机 ID 隔离，提交操作时校验版本，重复点击和旧页面操作不会重复扣资源。每次请求内完成玩家行动与 AI 回应，失败恢复到请求前状态。
- `prototype/effects.js`：与本地工作台共享的十二类 SVG／Web Animations 特效；`game-effects.js` 将引擎状态变化与实际行动映射为播放效果，数字来自实际生命变化。
- `prototype/app.js`：显示服务端状态、选目标、阶段播放和伤害／阵亡反馈。`cards.js` 为原版展示数据，修改过的规则以界面说明和实时攻血为准。
- `prototype/engine-client.js`／`engine-worker.js` 与 `scripts/browser_bridge.py`：提供与本地 HTTP API 相同的数据格式，让 Pages 在浏览器内运行同一引擎；本地模式继续访问 Python 服务。静态构建时写入独立运行配置。
- 原版美术引用 `references/artifact-classic/assets/`，自制夜魇近战兵引用 `prototype/assets/units/dire-melee.webp`，原件与清单在 `assets/custom/`；通用图标／边框仍由 CSS／SVG 绘制，尚未补齐原版客户端 UI 和音效。

## 验证

当前 V0.3 通过 123 项 Python 检查；本地 HTTP 与静态浏览器版均用真实按钮完成种子 13 的 164 次操作，在第 28 轮结束。新增预测、长按、路径与素材库检查见 [V0.3 发布记录](../docs/releases/v0.3.md)。以下 V0.2 数值保留为历史发布记录。

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
node --check prototype/app.js
```

V0.2 发布时通过 116 项 Python 检查和六个种子的完整回归局。Chrome 的 320×568、375×667、390×844、430×932、1440×900 视口均完成布局检查；固定种子 13 通过真实按钮执行 117 次操作，第 18 回合正常结束，并验证刷新恢复、导出和重新开局。

浏览器检查脚本可传给 Playwright CLI 的 `run-code`：

- `scripts/check_mobile_prototype.js`：读取 `scripts/fixtures/playthrough-13.json`，执行真实按钮的完整回归。
- `scripts/check_game_feedback.js`：开启动画检查沟壑与交战，同时检查固定运行环境缓存。
- `scripts/check_battle_readability.js`：检查预测标记、长按、绿／红阵营、中央建筑、上一手路径／日志及本地素材库。
- `scripts/check_battle_effects.js`：开启动画再跑完整对局，检查十二类效果出现、动画清理和结局一致。

具体结果、运行文件大小、公网发布标识和局限统一保存于 [V0.2 发布归档](../docs/releases/v0.2.md)。临时截图／JSON 位于忽略的 `output/`，其他机器不默认具备这些文件。桌面视口模拟不替代实体手机验证；运行时可从缓存读取，也不表示完整游戏已经支持离线。

移动端美术为 WebP：头像宽 128 像素、详情卡面宽 352 像素、图标宽 96 像素；图片总量从 43,018,613 降至 1,133,930 字节。原版 PNG 保留在参考库，Pages 只发布压缩副本。安装 `cwebp` 后可运行 `python3 scripts/compress_assets.py` 重新生成，不是正常启动或部署的必需步骤。
