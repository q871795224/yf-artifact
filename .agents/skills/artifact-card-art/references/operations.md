# 提交、返工与资源归档

## 提交前

1. 核对本次类别、目标数量与是否只提交。先查[分类索引](../../../../assets/art-library/README.md)防止把旧稿、同物多版本或已提交任务当缺项。
2. 通过当前安装的 `migoo-imagegen` skill 使用 `yf-migoo models image --json`、`account --json` 与 `policy`。默认本项目 Flare／1K／9:16，实际支持项和标价每次以平台为准。
3. 参考图先核对实际对象并裁掉白边、UI、气泡和无关分镜；原图另留，裁图用途写清。身份图在前，Classic 画法图在后，顺序与提示词一致。

历史曾每日刷新 100 免费额度、模型标价 1K 5.33，但余额变化与并发任务流水不完全对齐。不要按旧会话余额、某一笔 `chat_round` 或跨日差额计算本批单张成本。免费余额为零时不绕过封装入口、不自动充值或换付费方案；到暂停时间后按基础 skill 要求取得新的续用日期。

## 可复用提交器

```sh
python3 scripts/migoo_submit_batch.py <batch.json> --dry-run
python3 scripts/migoo_submit_batch.py <batch.json> --jobs 2
```

格式和行为以[提交器说明](../../../../scripts/migoo-submit-batch.md)及脚本为准。现有兼容字段 `heroes[].hero` 在装备批次中也存物件 slug；它是任务标识，实际类型看 `kind` 和提示词，不将装备当英雄绘制。

每个任务目录保存 `request.json`、`prompt.txt`、`notes.txt`。有原成图的修订可设 `source_task`。参考图可用本地路径、已核对的 media ID 或公开官方 URL；跨账户不假定旧 media ID 可用。缺少旧 `output/` 文件时，提交器可经[参考归档映射](../../../../references/card-art/catalog.json)找到仓库副本。

平台当时最多同时生成三张，名额由整个账户共享。用 1–2 并发留出余量，即使先查任务列表，其他会话也会抢占名额。只对平台明确说“并发忙且没有开始”的失败补交，保留每次任务号；脚本自动补交有上限。超出后先看失败原因与实际空位，不把失败计为提交成功。

网络结果不明、断流或超时时，有任务号就查原任务，没有就查 `task list`，不直接重建。已完成图的再生成与修改会消耗新额度，不能用“重试”掩盖新的生成。

## 状态与交付

| 证据 | 可以汇报 | 不能顺带推断 |
| --- | --- | --- |
| 平台任务号与受理状态 | 已提交 | 已出成图、已验收 |
| 返回 `completed` | 平台已完成 | 本地已有文件 |
| 图片文件、尺寸与 SHA-256 | 已下载／已归档 | 用户认可、身份画对 |
| 用户明确看图通过 | 对应图或批次已认可 | 所有后续批次自动通过 |
| 游戏映射与实际验证 | 已接入游戏 | 已推送或已发布 Pages |

用户当前经常在 Migoo 自行看图，只需提交并给数量与任务号。不要额外为看图反复下载、盯结果或加批准关卡。需要本地看图、对照页或接入游戏时再按本次指令执行；候选、原图、缩略图和实际采用图分别留档。

## 资源维护

```sh
python3 scripts/art_library.py
python3 scripts/art_library.py --archive-references
```

普通刷新只生成分类索引；`--archive-references` 把已用本机图片按哈希复制到 `references/card-art/files/`，已有相同内容就复用，原图和目录保留。不要为整理而删除失败图、旧方向、任务回包或用户提供图；可标成探索、被修订或仅本地。

原始日志与任务回包可能有临时签名下载 URL，保留本地但不作为公开 GitHub 的资源索引。仓库保存提示词、任务号、规范化状态、参考来源和无凭据的分类资料。工作区会话原文和个人账户资料也不整份发布。

本 skill 不包含新的生图授权。整理、重建索引、验证脚本与推送资料时，不顺便提交新生成任务；生成图接入游戏和发布 GitHub Pages也须有对应任务授权。
