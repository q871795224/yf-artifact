# 原创法术与英雄技能

## 原创法术

用户认可的路线是：沿用此前已生成的普通单位作为出场对象，另用两张 Classic 无框原画控制画法；没有角色的法术可直接描绘环境、物件与空间变化。

参考顺序在提示词里逐张说明：前 N 张分别是哪位角色、谁是目标，最后两张才是画风参考。已有单位的脸形、衣装、招牌器物保持，动作、镜头和场景重新绘制。不要因用了自制单位图，就让它覆盖 Classic 的笔触和用光。

法术画面以“正在发生什么”为中心：

| 机制 | 画面中应看见 |
| --- | --- |
| 缠绕／定身 | 束缚触点、绷紧的腿或手臂、急停与重心反应 |
| 推拉／位移 | 施力方向、身体偏斜、接触处、飞散物的共同动向 |
| 强化／护持 | 发生变化的部位、材质或防护接触，不只是站着发光 |
| 环境／空间 | 裂地、涌流、悬石、回时等具体变化与近中远景关系 |
| 多目标 | 明确的尺度差与纵深，效果对应到具体目标 |

精细与最亮处集中到作用点，其他角色与背景允许半身或局部入画。“单位立绘必须全身”不适用于法术场景。效果用绘画表达，不画棋盘格、箭头图标、数字说明、技能图标或漫画气泡。

可复用样例：[凝霜缚足等首批 10 张](../../../../assets/migoo/unit-cast-spells-01/briefs.json)、[声波、孢雾、重量与日蚀等追加 20 张](../../../../assets/migoo/unit-cast-spells-02/briefs.json)。用户均明确认可效果并要求扩批。

## 英雄技能

先核对官方英雄、技能名、`ability_key` 与说明，再决定谁施放、打到谁、如何反应。项目已保存的 [10 张技能](../../../../assets/migoo/hero-skill-scenes-01/briefs.json)与[追加 20 张](../../../../assets/migoo/hero-skill-scenes-02/briefs.json)记录官方来源、出场对象和参考顺序。

官方数据查询形式：

```text
https://www.dota2.com/datafeed/herodata?language=schinese&hero_id=<id>
```

施法者使用对应官方英雄参考；目标可以是另一位英雄或本项目已有单位。召唤物的身份要另查对应官方图标或客户端图，不能凭技能名字编一个物种。英雄仍按原版外观绘制，但场景的视觉中心是技能作用，不必把英雄完整站在正中。

建议的最小叙事：`施法者的位置与动作 → 可见的作用路径／区域 → 目标或地形的变化`。表现多名目标时先安排不同尺度与纵深，保留几条主要效果线；避免人物、发光轨迹与杂物抢成同等精细。

## 已观察到的优劣

- 蓝色法术混用旧自制风格图后，用户认为画法更像自制图；改为两张 Classic 后，明确反馈“局部高光很棒”。已有角色图要标成身份参考。
- 五点落雷分叉过多容易读成雷暴，涡流推拉只有光圈而身体动作弱；需要收敛主路径、突出落点和受力。
- 冻足、拉拽、缴械、声音、材质腐蚀与环境变化提供了更多构图，能拉开整批差异；不把所有法术都变成不同颜色的光束。
